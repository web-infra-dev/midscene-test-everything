# Midscene Robotics

[English](./README.md) · 简体中文 · [Midscene.js](https://midscenejs.com/zh/)

通过摄像头和机械臂，或 Mac 蓝牙键鼠，让 Midscene 操作真实触摸屏和 iPhone。提供浏览器工作台、Node.js SDK 和 DOBOT MG400 适配器。

## 快速开始

准备带触控笔的 MG400、摄像头和触屏设备，使用 Node.js `^20.19.0 || ^22.12.0 || >=24.0.0` 和 pnpm 9.3.0。

```sh
pnpm install
pnpm build
pnpm dev
```

打开终端输出的网址。Playground 会探测 `192.168.1.6` 和 `192.168.2.6`，优先连接唯一一台可响应 Dashboard 指令的 MG400。如果只有一台控制器应答，但它拒绝 Dashboard 指令，适配器会自动请求切换到 TCP/IP 开发模式，并重新查询确认。探测期间也可以点「跳过，查看相机」。两个入口使用同一个相机工作区，可以稍后在侧栏点「连接机械臂」。连接或断开后工作区保持打开；所选相机和视图仍可用时会保留。如需指定地址、端口或配置网口，使用 `pnpm dev --manual` 启动。连接成功后按引导标定并配置模型，即可执行任务。运动前确认工作区安全，需要停止时点击「停止机械臂」。点击「停止机械臂」或发生急停（包括控制器上报的急停）后，确认机械臂已静止、停止条件已解除，再点击「检查恢复」。重启服务不会解除这个要求。其他中断会在操作结束后自动检查控制器就绪状态和最新位姿。如果反馈暂不可用，状态刷新或发起新操作时会再次检查。

没有机械臂时，可运行 `pnpm dev:mock`（或在 `pnpm dev` 前设置 `ARM_PLAYGROUND_MOCK=1`）。Playground 会启动一台使用该型号默认运动参数的模拟 MG400，并立即连接。模拟器不会建立控制器连接，也不会驱动真实硬件，可用于界面、标定设置和相机映射调试，但不能作为实测标定结果。相机仍是真实相机。

点击相机预览中的「识别屏幕标记」或机械臂配置中的「屏幕标定」，Playground 会使用这台相机已经连接的手机。手机配对链接自动优先使用电脑当前的 Wi‑Fi，排除机械臂有线网段和虚拟网卡。首次连接时点击「连接手机」，用手机扫码打开标定网页，并保持页面在前台；断开后，在手机上重新打开该网页。可以先跳过机械臂连接，识别标记并保存透视。连接后，已配对手机的结果归到原来绑定的屏幕；新手机可以使用尚未绑定的默认屏幕。打开对应屏幕的标定向导即可在原手机上继续，无需再次扫码，其他手机不会覆盖已绑定屏幕的结果。手机优先请求系统常亮；安卓不创建唤醒视频，避免全屏被浏览器播放器接管，仅在 HTTPS 页面使用系统常亮。点手机上的「进入全屏」后，Android 通过浏览器全屏 API 进入全屏，并保持扫码时手机的横竖屏方向，不会主动切换系统方向。鸿蒙按提示进入全屏。Playground 会自动补偿鸿蒙全屏时仍可能保留的顶部状态栏。iOS 在 Safari 中选择「分享 → 添加到主屏幕」，再从主屏幕图标打开。若「相机映射」提示轻点，请在 iPhone 网页上点一下，并保持手机不动，等待相机识别标记。网页位置尚未确定时，预览会隐藏这台手机之前保存的轮廓。iPhone 的避让验证棋盘格会铺到状态栏下方，并根据顶部安全区域加高首行。只有手机进入所需模式并显示标记后，才开始采图。返回 Playground 首页后，手机标定页保持全屏，下次运行可直接复用。

Playground 对同一批 8 张相机帧统一解码，按屏独立拟合。有效帧不足时，仅对受影响的屏幕自动重试最多两轮，每轮重新采集 8 帧。高置信度结果可自动应用，置信不足或部分成功时可逐屏复核，只重试受影响的屏幕。依赖图像的运动仍要求透视和页面映射有效。无论机械臂是否连接，都可以点击「编辑透视」，用所选相机的最新帧调整透视。仅相机模式下，识别完成后也会打开透视校正界面，可对照原始画面与校正结果、编辑四角、设置输出尺寸与旋转，最后点击「使用此结果」保存。 保存后，相机预览会按所选屏幕保存的宽高比显示校正画面，可在「原始画面」和「校正画面」之间切换。仅相机模式下，「清除透视校正」会删除保存的屏幕轮廓、输出尺寸和旋转，并返回原始画面。连接机械臂后，从预览或「相机映射」清除透视会解除所选屏幕的映射，并保留其已存透视。

Playground 和 SDK 已暂停屏幕偏移检测。以前记录的偏移告警不会拦截截图、点击或标定。标定仍要求相机提供与已保存分辨率一致的近期画面，并校验映射指纹。

预览中的绿框表示已应用的透视范围。页面映射校验失败时，手机会继续显示标定码，可以直接重试「确认相机映射」。六个标定码中只要能唯一识别出任意四个，就可以建立相机映射。出现漏检时，系统会增强对比度并重试一次。所有可见标定码都参与最终映射。评估精度时，系统用外侧标定码拟合，再用可见的内侧标定码独立校验。两个内侧码均被遮挡时，只显示拟合误差。从所有标定码一起评分的旧版本升级后，首次检查映射时会重新测量标定码，再缓存新结果。每个可见标定码取四个角点中最大的定位误差。以手机页面短边为基准，拟合码的平均误差建议 ≤0.75%，最大误差建议 ≤1%；独立校验码的平均误差建议 ≤1.5%，最大误差建议 ≤2%。这些数值衡量相机映射精度，机械臂的实际触点误差由屏幕标定单独测量。每项建议值有 10% 的相对容差，超出容差的映射仍可查看和复核。

引导依次完成「触控工具 → 相机映射 → 示教安装 → 屏幕标定」。切换同一相机下的屏幕时，实时预览和已选的预览标签页会保留，当前操作区保持可见并暂停响应，待目标屏幕的配置和标定状态都就绪后一起切换。被选中的手机会短暂显示蓝色边框和「已选中此设备」。步骤栏固定在顶部，操作区与实时相机预览共用一个滚动区；宽窗口左右并排，窄窗口把预览放在操作区上方。预览区可以切换「实时预览」和当前步骤的「配置示意图」，无需离开当前步骤。在「示教安装」中，先在屏幕中心上方 20–50 mm 记录标定参考位。选择「示教相机边界」，从参考位朝相机方向直线移动，为整条机械臂留足空间，在距离参考位至少 20 mm 的安全边界记录位置；确认通行区域后保存安装示教。同一机械臂、工具、相机的多块屏幕共用这份示教；机械臂或工具几何变化后需重新示教。前往相机侧边界、手动返回参考位和自动采样前返回参考位，都使用当前配置的动作速度和加速度。如果起点读数显示笔尖偏出相机侧边界不超过 0.5 mm，首个通行路点会投影回示教边界面。偏差更大时，系统会在移动前拦截。参考位定义普通横移的最低通行高度，接触探索仍受向下搜索距离限制。

在相机原始预览中，蓝色圆点表示标定参考位，黄色菱形表示已记录的安全避让位。屏幕几何拟合前，参考位显示在映射屏幕的中心。拟合后，标记按笔尖在屏幕平面上的垂直投影绘制。已记录的相机侧边界点落在画面内时，以紫色三角标出。位置超出视野时标为「画面外」，相机侧边界会显示在预览边缘。

MG400 使用竖直向下的触笔时，「触笔长度」可以留空。确认负载并完成安装示教后，自动标定会拟合笔尖触屏时的法兰位姿；工具的物理长度仍为未知。更换或重新安装触笔后，请重新示教并标定屏幕。填写实测长度可使用笔尖坐标。重新打开机械臂配置时，引导会根据已保存的进度打开下一步，前几步已完成时直接进入「屏幕标定」。需要修改时，可以点击顶部的对应步骤。使能时使用已保存的负载，仍需操作员确认。同一台机械臂的已保存配置使用同一工具时，尚未配置的屏幕可跨相机复用这份测量值。如果旧屏幕全部已归档，且记录使用同一工具，新屏幕仍可复用这些测量值。

探测运动确认到位、手机读数明确后，如果采样或拟合未通过，机械臂会先预检回程路线，原地抬笔，再回到本次记录的标定参考位，等待重试。停止、断连、手机读数不确定或运动结果未确认时会中断自动回位。

每次探测到位后，机械臂保持静止，等待手机两次读数一致，两次读数至少间隔 100 毫秒。在下探下限、最终按压或滑动终点，如果手机初次回报未接触，会先等一个完整的手机上报周期（750 毫秒）再请求确认。触点出现较晚或坐标变化时，会在同一高度再读一次。五秒内缺少本步回包、浏览器取消触点或按压时短暂接触后又释放，都会在当前位置停止采样。失败审计的 `detail.phoneObservations` 记录最近的探测高度、目的、手机回包序号，以及从发出请求到收到回包的用时，其中包含浏览器处理时间。

采集、拟合并自动检查边界后，有效示教会授权自动计算相机安全位：依次预检左右两侧出口，再考虑相机对侧；先抬到示教通行高度，再以配置速度和加速度的 10% 移动。实测到位后才记录安全位。停车位置会避开已知屏幕的合并范围，包括屏幕之间的空隙。候选均不可达时回退手动记录安全位；已经提交的运动失败则中断标定。检查结果后确认保存。

网格均方根误差和独立验证点的最大触点误差同时显示毫米值和占实测屏幕短边的百分比，测量复核、快速边界验证和自动验收统一使用 1.5% 和 2% 的建议值。计入 10% 相对容差后，网格均方根误差超过 1.65% 或独立验证最大误差超过 2.20% 时提示复核。高度误差按 2 mm 表面补偿范围计算。各项质量指标均有 10% 的相对容差，例如覆盖率目标为 60%，实测 54% 仍在容差内。超出容差会保留采样和拟合结果。复核后可直接继续边界验证，也可以重新采样。保存前需要完成边界验证并记录安全位置，批量标定遇到质量提示时进入人工验收。

在「相机映射」中，用每台设备打开手机页，再在电脑上选择页面及观察它的相机。二维码也可用于打开手机页。浏览器会保留稳定的页面身份，首次标记检测会一起标定已连接的屏幕。在已有配置中新增手机时，会标定配对时分给它的屏幕。已释放的手机如果仍未绑定，则会分配新屏幕。应用后，「原始画面」显示所有已保存的屏幕轮廓。选择屏幕并切换到「校正画面」，即可按保存的宽高比单独查看这块屏的实时透视画面，完成机械屏幕标定前也能查看。「返回首页」释放页面会话，「清除透视」保留该屏已保存的结果。在标记列表中点击「移除」会归档该屏幕，手机可以重新配对。刷新或重新打开标定后，列表只显示剩余屏幕。在手机连接窗口中点击「移除页面」，还会删除该离线手机的页面身份和所绑定屏幕的透视。

机械臂已连接且所选屏幕已完成标定和相机映射后，可在机械臂状态栏打开「控制」。点击为点击，按住至少 500 ms 为长按，拖动为滑动，手势在释放时执行。动作完成且机械臂就绪后，可以直接继续操作。在「原始画面」中，指针下的屏幕即为目标；在「校正画面」中，目标为当前选中的屏幕。切换同一已完成批次内的屏幕时，Playground 会复用已确认的共用安全位，或在已确认的通行区域内自动规划路线。开始动作前会核对机械臂当前位置并检查移动路线。无法自动规划时，可在机械臂配置中验证该方向的切换路径。任务或标定运行期间，以及机械臂未就绪时，控制不可用。

安装示教完成后，「屏幕标定」从「采集标定点」开始。示教时选中的屏幕可直接复用参考位；换到尚无已知起点的屏幕时，在采样前记录一次该屏中心上方 2–5 cm 的起点，相机边界和通行高度沿用已有示教。服务重启后，打开原屏幕会重新关联已配对的手机。向导复用已保存的透视。手机布局、相机指纹和工具几何一致时，直接恢复页面坐标映射。如果只缺页面映射，向导使用已保存的校正画面检查标记，成功后自动继续。透视缺失或失效时进入「相机映射」进行检测。每块屏首次运动前（包括批量标定），若控制器短暂断连或负载回读暂不可用，向导会短暂等待。确认尚未发送运动指令后，向导会重新核对已保存负载和机械臂就绪状态，使用最新位姿重新检查路线并继续。控制器通道重置只会丢失负载证据，不会改变控制器配置：各运动前检查和命令之间的检查都会等待适配器重新读取并确认已保存负载，因此批量标定中途遇到重置不再让本轮失败。只有控制器实际报告的负载不一致，或证据在等待期限内始终未恢复，才会阻止运动。若控制器负载与保存值不一致，请同步工具负载。采样中若只有手机或控制器连接中断，原设备重连后会重新核对屏幕映射、位姿及静止无报警状态，清除本轮采样点并返回采样准备。再次采样需手动启动。手动点击停止或急停后，待机械臂静止且停止条件解除，点击「检查恢复」。采样运动意外中断或超时时，控制器会自动检查恢复状态。在当前页面点击「重新开始标定」即可发起新一轮采样。重新确认工作区后即可开始采样。只有一块已映射屏幕时，「屏幕标定」直接打开该屏幕的标定页面。有多块屏幕时，「标定 [屏幕名称]」只标定当前选中的屏幕。进行中如需换屏，先取消本次标定。重试会保留该屏幕的手机配对和相机映射，从零开始采样；通过验证并保存后才会替换该屏幕原有的结果。「批量标定多个屏幕」有独立的确认入口。等待手机或映射时会加快刷新屏幕状态，采样和共用安全位验证期间暂停刷新屏幕列表，标定队列进度继续更新。连接机械臂时会先检查标定队列所需的运动前置条件，缺失或未确认的工具负载会在开始标定前显示在机械臂状态栏中。连接已使能的 MG400 时，Playground 会短暂等待新的控制器反馈，确认当前工具负载。批量标定入队前及每块屏幕开始采样前，都会检查控制器状态和所选工具的已保存负载。负载不一致或未确认时，已使能的机械臂状态栏会显示「同步工具负载」，确认后按钮隐藏。

「屏幕标定」保留原版逐屏卡片、计划顺序、摆位提示、运行历史与队列确认。整个标定及人工等待期间共用并占用同一个 Controller 队列。单屏标定排队时，也必须等到取得队列使用权才能采集。已有结果提供实测起点；新屏幕可从已接受屏幕推算平面，或等待人工摆位。启动前需确认屏幕固定，以及适用时的跨屏通行区域。 批量默认使用「普通」逐点采样。选择「快速」后，每块屏使用滑动采样，需确认所有屏幕均已水平固定。两种模式默认在采样质量和完整的悬停、接触边界验证通过后自动验收，也可选择逐屏人工验收。批量等待当前手机页面就绪，逐屏完成验证并保存结果，随后转场至下一块。移动到共用安全位前，会先确认所有配对手机能显示验证图案。若检查失败，可在批量面板重试避让并保留已保存的逐屏结果。最后一块结束后，才根据实测轮廓及跳过屏幕的保守估算搜索共用安全位。避让时法兰和笔尖须向远离相机的一侧移动，目标与已示教的相机边界至少相隔 20 mm。每次到达可行候选位置后，配对手机会短暂交替显示棋盘格。只有新鲜相机帧确认各屏都能看到预期图案，才记录该位置。部分遮挡时会尝试下一个通过路线检查的位置，每轮最多尝试三个新候选，XY 位移限制在距实测搜索起点 500 mm 内。候选耗尽或画面无法验证时停止搜索。各屏的标定结果在共用安全位通过画面检查并统一保存后，才可用于任务。重试或恢复时沿用所选采样模式及已记录的共用安全位。重试、跳过只影响当前屏。停止优先中断待执行命令，退出拖动模式后再释放队列，并保留已完成结果；服务重启后保留历史并停止，等待显式恢复。恢复时保留已确认的通行高度，并重新核对几何、示教、屏幕映射，以及当前位置是否仍在确认的通行区域内。完成后通过屏幕选择器切换预览与任务。SDK 中为每屏设置独立的 `RobotArmDevice.id` 和 `screenId`，物理 `camera` 保持相同。

顶部扬声器控制安全提醒和进度音效。自动避让相机时，标定向导会停留在当前页面，并在避让开始时语音提醒操作员让开。标定结果可以保存时，语音会提醒你确认；批量标定结束时，语音会提醒你核对已保存的结果。其他机械臂运动、进入拖动模式、反馈中断、报警和停机时会有简短语音。设置说明、常规标定进度和结果在界面显示，每次采到样本有短音提示。

采样点固定内缩 10%，目标覆盖完整屏幕的 60%。默认选中「快速」，滑动采样；「普通」模式以配置动作速度和加速度的 10% 逐点探测，最后下压采集触点时，两者提高到配置值的 25%。网格采样时，手机与网页示意图同步显示九个编号采样点，虚线连接采样顺序，蓝圈标出当前目标，绿点标出已记录的实际触点。快速采样的首个网格点未检测到触摸时，系统朝初始实测触点内移 3 mm 重试一次，下探限位保持不变。快速采样失败时，点击「确认重试」后才会切到普通模式重新采样。快速模式下，一次勾选即可确认屏幕水平固定、配置就绪且工作区净空。在机械臂标定中，可点「上一步」回看已完成步骤的测量记录，再点「下一步」返回当前进度。

刷新单屏标定页会恢复本轮进度，可以继续查看测量值或已保存的结果。等待边界验证时仍可取消本次标定。中断后页面会显示出错的步骤，控制器需要恢复时可点击「检查并恢复控制器」。在 SDK 独立页保存后，点击「完成标定」即可把结果返回脚本。再次从 SDK 发起标定会开始新的一轮，即使这块屏幕已有保存的标定结果。

安全位的画面验证根据手机上报的网页视口和相机中的棋盘格定位，排除网页之外的系统栏。验证允许少量零散漏检，网页内部各格仍须达到局部检出要求。如果首组画面检出率未通过，机械臂保持原位，相机补采一组画面再决定是否继续搜索。批量面板分别显示已保存的屏幕标定结果和待确认的共用安全位。安全位待确认时，可查看实时画面后人工确认当前位置。控制器检查静止时的实测位置是否满足安全位条件，并原地记录确认结果。

当前相机下的所有屏幕就绪后，点击「完成标定并返回」回到 Playground。首页会重新检查当前生效的标定，再显示任务界面。

屏幕列表和批量标定计划在判断哪些屏幕已标定时，会忽略已归档屏幕的工具配置。如果保存的标定与当前相机映射不再匹配，界面会显示「标定已保存，相机映射已变更」，批量标定也不会用这条记录定位。

## iOS HID（实验中）

需要 macOS、用于编译原生辅助程序的 Xcode Command Line Tools，以及 iPhone。手机无需安装 App。安装依赖并构建后，启动专用工作台：

```sh
pnpm dev:ios-hid
```

脚本可以使用 workspace SDK 或打包后的 SDK：

```js
import { IOSHIDDevice, IOSHIDAgent } from '@midscene/ios-hid';

const phone = new IOSHIDDevice({ name: '测试手机', screen: { source: 'usb' } });
try {
  await phone.connect();
  const agent = new IOSHIDAgent(phone);
  try {
    await agent.aiAct('打开设置');
  } finally {
    await agent.destroy();
  }
} finally {
  await phone.destroy();
}
```

模型使用 Midscene 的正常配置方式，凭据不写入设备配置。Playground 在自身界面内完成画面选择、配对引导和摄像头校正。 AirPlay 保留首页蓝牙选择；启动接收器后，右侧展示接收器名称与配对码，等待投屏不视为截图超时。收到首帧后才启用验证。接收器设置状态通过 SSE 推送，不轮询状态；通过 UxPlay 客户端统计和断开事件区分静止画面、连接中断与视频停滞，新画面到达后恢复预览。「停止接收器」释放会话，启动失败可重试。JS 脚本的 USB、AirPlay 设置通过终端引导，只有摄像头校正会打开浏览器；首次选择与绑定设备需要交互式终端，无人值守脚本可复用已在 Playground 配置的设备。连接时：通过 USB 信任 Mac，在 iPhone 蓝牙设置中配对这台 Mac（使用 Playground 提示的 Mac 名称），启用辅助触控（AssistiveTouch），预览画面并确认蓝牙连接属于同一台手机。检测指针方向时，保持静态、明亮画面。内部自动生成设备 ID，`name` 用于选择已保存配置；后续脚本省略 `screen` 即可复用画面来源。

指针测量会等待新画面中的起点和终点稳定。每组移动独立测量三次，至少两次一致才采用中间样本；重复样本随移动配置保存，预测与实际位移的复核误差记录在 `midscene_run/log/ios-hid-pointer.log`。精度门槛保持不变。

AirPlay 恢复复用投屏引导，展示接收器名称和配对码，等待手机重新投屏后，自动检查已保存的蓝牙绑定并验证输入，无需再次点击确认。接收器启动、状态变化及进程异常记录在 Host 工作目录的 `midscene_run/log/ios-hid-airplay.log`，用于排查画面中断。

支持 `usb`、`camera` 和 `airplay` 三种画面来源。摄像头首次设置包含四角透视校正。AirPlay 需要在 Host 的 PATH 中提供 UxPlay 1.74+、相关 GStreamer 解码器，并开启 macOS 隔空播放接收器以支持点对点发现；辅助页会显示接收器名称与配对码。SDK 不内置或自动安装 UxPlay。

IOSHIDAgent 默认包含简短英文指引：中文通过屏幕键盘慢速点击字母和候选词，并检查已提交的文本；这段指引会与按优先级选中的用户 aiAct 上下文合并，不改变其他 API 的上下文。Input 动作说明也明确要求非 ASCII 文本改用页面建议或屏幕键盘；不支持的文本会在清空或输入前拒绝，并提示 Agent 改用其他动作。底层 Input 仍只支持 ASCII，不代表所有 App 的自动中文输入均已验证。

设备提供 `home()`、`back()`，Agent 的动作列表同时包含 `Home`、`Back`。Home 发送外接键盘的 Command+H 快捷键（部分 iPhone 会忽略 Consumer AC Home）；Back 执行左边缘右滑，仅适用于支持该手势的页面。两者沿用设备队列、取消与新画面检查。目前不提供 AppSwitcher 动作。

首次设置或重新测量时，Host 先验证指针方向，再通过画面帧差建立每台设备的移动量表：横纵方向分别测量 2、4、6、8 个 HID 单位，对角方向单独测量 (2,2) 和 (4,4)，使用与拖动相同的目标 16 ms 发送间隔。每组等待起终点稳定，三次测量至少两次一致后采用中间样本；随后进行独立的横、纵、斜向复核，全程不点击。稳定的偏差会修正对应量表项，必须再用新动作独立验证通过才保存，最多修正三次。规划器只使用实测报告及其符号镜像，不再外推二次曲线；这仍假设正反方向对称，悬停复核不代表应用的实际滚动距离。无法测量或持续不稳定时仍不能进入工作台。首次滑动直接复用量表。样本、重复测量、报告位移、画面几何、复核误差和算法版本按设备保存在 `~/.midscene/ios-hid/devices.json`；版本 3 会淘汰旧的二次曲线配置。重连时若绑定和画面尺寸匹配，直接复用已验证的方向和量表，不移动指针；缺少配置、配置不兼容或取消勾选复用时才重新测量。绑定包含蓝牙身份、画面来源、尺寸、方向和摄像头校正。如果修改了辅助触控追踪速度，或指针方向改变但画面尺寸未变，需要取消勾选复用并重新测量，这些设置无法通过 HID 读取。首次测量请保持明亮静态画面，不会额外打开手机辅助网页。

拖动使用向量长度不超过 8 个 HID 单位的相对报告，目标发送间隔为 16 ms，及时起步，末段温和减速并保持移动直至松开。规划器在合法整数移动量中搜索，并累计补偿量化误差。必要时可将过短的计划时长延长至 2 秒（主动指定更长时长仍支持到 5 秒）；仍然无法规划时，在按下前报错，不发送不完整的拖动。松开后用绝对定位恢复指针位置，这不能补偿应用滚动距离。新的时序默认值仍需跨设备、跨应用真机验证。

USB 画面来源列表以「手机名 - 手机型号」（例如「我的 iPhone - iPhone 13」）展示 USB 手机；连接后的设备名称使用蓝牙手机名，不提供手填名称。型号通过 macOS MobileDevice 框架读取已信任的 USB 手机；无法读取或可靠匹配时仅显示手机名。SDK 脚本仍可传入 `name` 选择已保存配置。

更换画面来源、USB 设备或摄像头时，需要重新确认画面与蓝牙手机的绑定，系统蓝牙配对会保留。指定 `cameraId` 时，辅助页只提供该摄像头；切换摄像头需要重新选择屏幕四角。

原生进程由 Host 按需启动并管理：蓝牙共用一个助手，USB 发现共用一个长期运行的助手，刷新复用同一个发现会话；各 USB 画面和摄像头采集流按各自会话管理。USB 发现不会启动录屏，也不代表当前一定能收到新画面。Host 关闭时结束发现助手，助手异常退出后在下次请求时重建。

本机唯一 Host 持有 iOS 采集和蓝牙会话，不依赖脚本持续运行。配置和 Host 发现信息保存在 `~/.midscene/ios-hid/`，启动问题记录在 `host.log`。重新构建后，可用 `pnpm ios-hid:stop` 停止共享 Host，再启动工作台加载新版本。`destroy()` 释放设备占用，`agent.destroy()` 只释放 Agent 资源；失联客户端在 30 秒后回收。Host 默认监听本机地址并要求令牌；远端可通过转发连接，使用 `new HostClient({ url, token })`。`/devices` 列出已保存设备，`/tasks` 接收设备 ID、任务指令和请求 ID，每台设备独立排队。任务记录保存在内存中，服务重启后不重放任务。Host 执行任务时使用该进程环境中的模型配置。

迁移前已在一台 iPhone 上验证 USB 采集、BLE 点击、测量后的滑动、英文输入与中途取消输入。经典蓝牙已验证绝对指针移动和两台 iPhone 的独立路由；一台 iPhone 已通过连接时的方向检测、相对移动测量及横纵斜向独立复核，并保存曲线。新通道的点击、拖动、滚动和键盘输入仍需真机验证。键盘文本暂支持美式 ASCII 布局，需要切换到英文输入法，不支持的文本会在输入前拒绝。指针测量使用帧差，动画或低对比背景可能导致失败。AirPlay 集成和多手机并发仍需真机验证。Host 分别管理每台设备的画面来源与蓝牙连接占用；当前 AirPlay 后端同一时间只支持一个接收器。

摄像头输入复用机械臂的扫码辅助页、屏幕标记检测和校正组件。React 连接面板沿用原版 Playground 布局。每台设备拥有独立的上游 Playground 会话、Agent、任务与取消状态、报告和界面历史。设备标签页只切换视图，不会断开其他手机或停止其任务。「添加设备」进入 `#/connect/<workspace-id>`，工作台使用 `#/workspace/<workspace-id>`；Playground 服务运行期间刷新会恢复选中的设备及设置进度。连接处理期间首页保留表单，连接按钮显示 loading；异常通过全局提示展示。连接进度与工作区状态共用 SSE 推送，刷新或重连时发送完整快照，连接面板不再轮询；服务端保留画面健康检查。右侧预览旁的蓝牙图标打开设备详情。蓝牙订阅变化通过 SSE 推送工作台，画面健康检查独立进行；Host 在每次输入前要求新画面。蓝牙或画面异常时禁用执行，保留工作区和记录；右侧遮罩只提供「刷新」：按原配置重建连接，确认输入和新画面均可用后恢复；保留当前设备标签、Agent 与任务记录，不自动重放任务。正在执行任务时须先停止再刷新。脚本可调用 `device.refreshConnection()` 恢复同一个设备对象。画面来源在添加设备时确定，需要更换时移除后重新添加。移除只影响当前设备。新增连接中已占用的蓝牙手机标注「使用中」并禁用；USB 和摄像头列表保留全部已发现设备，已占用项标注「使用中」并禁用，数量包含这些设备，全部占用时提示「设备均在使用中」。每次绑定一台尚未分配的手机即可，已有设备可以保持连接。Host 继续负责资源占用检查。浏览器模型配置共用，任务记录、提示词历史按设备隔离。先选画面来源：USB 列出已连接手机，AirPlay 启动接收器，独立摄像头先选择具体相机。选择相机后即在连接界面显示实时预览，点击连接直接进入共用的扫码和校正流程；在带返回按钮的完整页面内按「扫码连接 → 相机校正」操作，复用机械臂的画面对照、检测工具栏和模型设置交互。相机校正提供标记识别和与机械臂共用的 AI 检测；模型设置复用 Playground 任务设置表单，支持表单／环境变量编辑和 Verify 连通性检查，机械臂校正弹窗同步生效。核对屏幕边缘后保存。手机需要能访问电脑的局域网地址；临时手机服务仅开放带会话令牌的辅助页和连接协议，不开放设备控制。网页标记无法确定完整屏幕边界时，保留手动调整与映射校验。

保存配置以「蓝牙设备 ID + 画面来源（USB、AirPlay 或摄像头）」唯一标识，连接时自动复用对应记录，设备名称使用蓝牙读取的手机名。取消勾选「使用已保存的校准配置」可重新校准并更新同一条记录。Host 启动时会合并相同组合的历史重复记录，保留最近保存的一条。

```text

examples/mg400/             SDK 示例
```

蓝牙输入使用经典 HID。连接页显示 Mac 实际蓝牙名称与已连接手机的名称，点击手机即可绑定到所选画面来源；只有一台可用手机时自动选中。已占用手机保留展示但不可选，断开时不会自动换选另一台。只有控制与中断通道都已连通才算已连接，仅有配对记录不算连接。原生连接、断开事件通过 SSE 推送，首次连接取得完整快照，不轮询蓝牙列表。名称来自经典蓝牙连接方，无法保证取得具体手机型号，因此不展示推测型号；同名手机附带地址后缀区分。HID 服务名为 `Midscene iOS HID`，经典蓝牙配对界面通常显示 Mac 系统蓝牙名称，应用不会修改电脑名称。迁移前的 BLE 配对记录可能需要在手机上忽略后重新配对；必要时从手机蓝牙设置重新连接，不保证 Mac 主动自动重连。旧 BLE 鼠标曲线会重新测量。该后端使用运行时检查的 macOS 私有蓝牙接口，已在 macOS 27.0.1 验证，其他系统版本仍需真机验证。

新增的 iOS HID 和 vision 包统一使用 Rstest。构建后分别运行：`pnpm --filter @midscene/ios-hid test`、`pnpm --filter @midscene/ios-hid-playground test`、`pnpm --filter @midscene/robotics-vision test`。

Host 在每次输入前检查画面健康状态，输入后在返回下一张截图前等待可见动画稳定（320 ms 静止窗口，最长观察 2.5 秒）；业务加载完成仍需按需使用 `aiWaitFor`。AirPlay 在最近客户端统计明确表示没有发送新视频时可复用静止画面，断开或解码停滞后不能继续复用。一个小型原生终端启动器让 UxPlay 的连接事件和统计即时输出，JPEG 视频保持独立管道。滑动规划可将过短的请求时长延长至 2 秒，以保持实测步长限制；请求时长是目标，不是硬性截止时间。

Playground 的 USB/摄像头恢复最多等待 3 分钟，避免复核失败后的完整重测被原有 60 秒上限取消；AirPlay 仍保留 10 分钟投屏等待时间。

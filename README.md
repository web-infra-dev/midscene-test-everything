# Midscene Robotics

English · [简体中文](./README.zh.md) · [Midscene.js](https://midscenejs.com/)

Let Midscene operate physical touchscreens with a camera and a robot arm. Includes a browser Playground, a Node.js SDK and a DOBOT MG400 adapter.

## Quick Start

Prepare an MG400 with a stylus, a camera and a touchscreen. Use Node.js `^20.19.0 || ^22.12.0 || >=24.0.0` and pnpm 9.3.0.

```sh
pnpm install
pnpm build
pnpm dev
```

Open the printed URL. Playground checks `192.168.1.6` and `192.168.2.6` and connects automatically to the only MG400 accepting Dashboard commands. If only one controller responds and it refuses those commands, the adapter requests TCP/IP development mode and verifies the change with a fresh mode query. Choose **Skip to cameras** even while discovery is running. Both entry points use the same camera workspace. Use **Connect robot** in the sidebar to connect later; connecting or disconnecting keeps the workspace open and preserves the selected camera and view when available. For a custom address, ports or network setup, start with `pnpm dev --manual`. Once connected, follow calibration and configure a model to run tasks. Confirm workspace clearance before movement; use **Stop robot** to stop. If recovery is required, check the stationary robot and select **Check Recovery**.

To work on the camera without a controller, run `pnpm dev:mock` (or set `ARM_PLAYGROUND_MOCK=1` before `pnpm dev`). Playground starts a simulated MG400 that publishes the model's setup defaults and connects immediately. The simulator never opens a controller connection or moves hardware, so it can drive the interface, screen calibration setup and camera mapping without a robot; its results are not physical evidence. Cameras stay real.

Choose **Detect screen markers** in the camera preview or **Screen Calibration** in robot settings. Both use the phone already paired with that camera. Phone pairing links automatically prefer the computer’s active Wi-Fi and exclude the controller’s wired subnet and virtual interfaces. Scan once to pair a new phone and keep the page in the foreground. You can skip the arm connection, detect the markers, and save the perspective first. On connection, a returning phone’s result goes to its bound screen; a new phone can use the unclaimed default screen. Opening that screen’s calibration continues on the same phone without scanning again. A different phone cannot overwrite a bound screen. The phone asks for a wake lock first. Android creates no wake video, so the browser cannot hand fullscreen to its media player, and uses the system wake lock only on HTTPS. Tap **Enter full screen** on the phone: Android opens the browser's element fullscreen and keeps whatever orientation the phone had, without forcing a rotation. On HarmonyOS, enter full screen when prompted. On iOS, use Safari’s **Share → Add to Home Screen**, then open the page from its icon. Detection waits for the required display mode and visible markers before capturing frames. The paired phone stays in full screen when you return to the Playground home page and can be reused for the next run.

Playground decodes the same eight camera frames for all target screens and fits each screen independently. If too few frames pass, it captures up to two more batches for the affected screens. High-confidence results can apply automatically. Review weaker or partial results and retry only the affected screens. When the live outline check detects a mismatch, the review can apply the visual result after confirmation. Image-based movement still requires a valid perspective and page mapping. With or without the robot, **Edit perspective** opens a fresh frame of the selected camera. In camera-only mode, detection also opens the perspective editor with original and corrected views. Compare the images, edit the four corners, choose the output size and rotation, then select **Use this result**. After saving, the camera stage switches to the corrected stream at the saved screen aspect ratio. Use **Original** or **Corrected** to switch views. In camera-only mode, **Clear perspective correction** deletes the saved screen outline, output size and rotation and returns to the original view. When connected, clearing a perspective from the preview or the **Camera Mapping** checklist releases the selected screen’s mapping and keeps its saved perspective.

Playground checks a saved screen outline using camera frames captured while its paired phone reports the calibration page visible in the required display mode. Switching apps, locking the phone, returning the phone page to its waiting screen, or losing contact pauses automatic outline checks. Returning to the calibration page resumes checks with fresh frames. SDK screenshots and touch actions, sampling and multi-screen batches continue to enforce previously confirmed mismatches while checks are paused. A confirmed mismatch blocks further image-based movement and shows the affected screen with a recalibration action. Low contrast or occlusion stays unverified and cannot clear a confirmed mismatch; recovery needs three distinct aligned frames spanning at least 1.5 seconds. Evidence is stored separately from geometry and does not change mapping fingerprints or erase accepted calibrations. Camera failure, stale frames, cancellation and phone layout changes cannot start a suspended movement.

The green outline shows the applied perspective. If page mapping fails, the phone keeps its markers visible so you can retry **Confirm Camera Mapping**. Camera mapping can proceed when the arm covers any one of the six phone markers. If a marker is missing, the camera retries once with contrast enhancement. At least five markers must decode uniquely. Each marker’s error is the distance at its worst-matching corner. Fit and independent check markers each have review targets of 0.75% mean and 1% maximum error relative to the phone viewport’s short edge. The mapping stays available for review when an error exceeds the target’s 10% allowance.

The wizard follows Touch Tool → Camera Mapping → Teach Installation → Screen Calibration. The step bar stays at the top. The controls and live camera preview scroll together, side by side on wide screens and with the preview above the controls on narrow screens. In the preview pane, switch between **Live Preview** and **Setup illustration** without leaving the current step. In Teach Installation, record the calibration reference 20–50 mm above the screen. Choose **Teach Camera Boundary**, move straight towards the camera while leaving clearance for the full arm, and record the boundary at least 20 mm from the reference. Confirm the clear corridor and save installation teaching. Teaching is shared by screens using the same robot, tool and camera; changed robot or tool geometry requires teaching again. Moving to either taught position, including the return to the reference before automatic sampling, uses the configured action speed and acceleration. The reference defines the minimum free-travel height and contact exploration remains bounded below it.

The raw camera preview marks the calibration reference with a blue circle and the recorded Safe Position with an amber diamond. Before the screen geometry is fitted, the reference appears at the mapped screen centre. After fitting, the markers show the stylus tip projected vertically onto the screen plane. A purple triangle marks the recorded camera-side boundary point when its projection is in view. An off-camera reference or Safe Position is labelled “outside frame”.

Saving **Touch Tool** records the measured length and payload before screen calibration. When you reopen robot settings, the wizard uses saved progress to open the next step, or opens **Screen Calibration** if the earlier steps are complete. Select an earlier step in the header to edit it. Enable uses the saved payload and still requires operator confirmation. An unconfigured screen on the same robot and camera can reuse the measurements when the saved setups agree on the tool.

Collect samples, fit and automatically check the boundary. If confirmed touch readings fail the sampling or fitting checks, the arm checks the return route, lifts vertically and returns to the recorded calibration reference before retry. A stop, lost connection, uncertain phone reading or unconfirmed move interrupts automatic return. With valid teaching, calibration preflights both lateral camera-avoidance exits before the opposite side, lifts to the taught travel height and moves at 10% of the configured motion speed and acceleration. Only measured arrival records the Safe Position. Parking clears the combined footprint of known screens, including gaps between them. Unreachable candidates fall back to manual Safe Position recording; a failed submitted move interrupts calibration.

At each stationary probe position, the arm waits for two matching phone readings at least 100 ms apart. When the phone initially reports no contact at the descent limit, final press or slide endpoint, the arm waits a full phone reporting interval (750 ms) before requesting confirmation. Late contact or a change in coordinates gets one more reading at the same height. A missing acknowledgement after five seconds, a cancelled pointer, or a brief contact lost during a press stops sampling at that position. The failure audit’s `detail.phoneObservations` records the recent probe heights, purposes, phone reply sequences and elapsed times from each request to its reply, including browser processing.

The grid RMS and maximum independent touch error are shown in millimetres and as percentages of the measured screen’s short edge. Their review targets are 1% and 1.5%, respectively. Height errors use the 2 mm surface compensation range. Each quality target has 10% relative slack, so 54% coverage meets the 60% coverage target with slack. Larger deviations retain the samples and fit for review. Choose **Continue to boundary verification** to use those samples, or restart collection. Boundary verification and a measured Safe Position are required before saving. Batches with quality warnings wait for manual acceptance.

In **Camera Mapping**, open the phone page on each device, then choose the page and observing camera on the computer. A QR code can open the page. Each browser keeps a stable page identity. Marker detection binds pages to screen targets. After applying, **Original** shows all saved screen outlines. Choose a screen and select **Corrected** to see only its live rectified image at the saved aspect ratio. This preview is available before physical screen calibration. **Restore Home** releases the page session. **Clear Perspective** keeps the saved result for that screen. Deleting a screen binding, deleting a saved perspective and forgetting an offline page are separate actions.

With the arm connected and a screen calibrated and mapped, turn on **Control** in the robot status bar. Click to tap, hold for at least 500 ms to long press, or drag to swipe; gestures execute on release. In **Original**, the screen under the pointer is the target; in **Corrected**, the selected screen is the target. Touching another physical screen requires a verified transfer route in that direction. The Playground asks before moving and refuses the action without movement when no route exists. Control is unavailable while a task or calibration runs, or when the robot is not motion-ready.

When the selected screen already has a taught reference, the guided calibration opens at sampling preparation. After a service restart, opening the screen reconnects its paired phone. The wizard reuses a valid saved perspective and restores its page mapping when the phone layout, camera fingerprint, and tool geometry match. If only the page mapping is missing, it checks the markers in the saved corrected image and continues after the mapping succeeds. A missing or invalid perspective opens Camera Mapping for detection. Before the first motion of each screen, guided calibration (including batches) briefly waits for transient controller connection or payload feedback loss. It resumes after confirming the saved payload, checking robot readiness, and rebuilding the route from fresh pose feedback. Sync the saved payload if the controller reports different parameters. If only the phone or controller socket drops during collection, reconnecting the same setup returns it to sampling preparation after a fresh stationary, fault-free controller and pose check. Partial samples are discarded. Start sampling again explicitly. Manual stops, emergency stops, and unconfirmed motion require operator recovery. With one mapped screen, **Screen Calibration** opens that screen directly. With multiple screens, **Calibrate [screen name]** starts only the selected screen. Cancel the current attempt before switching screens. A retry keeps that screen’s paired phone and camera mapping, starts with no samples, and only replaces its saved result after successful acceptance. **Calibrate multiple screens** opens a separate batch confirmation.

The Screen Calibration step shows the original per-screen cards, planned order, placement prompts, run history and batch confirmation. A batch holds the same Controller queue throughout exploration and operator waits. A queued single-screen session cannot collect samples before it owns that queue. Accepted geometry provides measured starts; newly mapped screens can use a plane estimate from accepted screens or wait for manual placement. Fixed screens and any computed transfer corridor require confirmation before starting. The batch defaults to Regular (individual probes). Select Fast for sliding sampling and confirm that all screens are secured horizontally. Both modes default to automatic acceptance after passing their quality checks and full hover and contact boundary verification. Select per-screen manual acceptance if needed. The batch waits for the current phone page, then verifies and saves its screen before moving to the next. Before moving to a shared Safe Position, it checks that all paired phones can display the verification pattern. If this check fails, retry parking from the batch panel to keep the saved screen results. After the last screen, it searches for one shared Safe Position using measured outlines and conservative estimates for any skipped screens. The flange and tool tip must retreat from the taught camera boundary and finish at least 20 mm behind it. At each reachable candidate, paired phones briefly display an alternating checkerboard. Fresh camera frames must confirm the pattern across every screen before the position is recorded. Partial obstruction triggers another preflighted candidate, with at most three new candidates and a 500 mm XY limit from the measured search start. Exhausted candidates or an unavailable camera check stop the search. Verified screen results become available for tasks once the clear shared position is saved to all results. Retrying or resuming keeps the sampling mode and the recorded shared position. Retry or skip affects only the current screen. Stop preempts pending batch commands and exits Drag Mode before releasing the queue. Stopping retains completed results, and a service restart leaves the history stopped for explicit recovery. Resuming preserves the confirmed travel height and rechecks geometry, teaching, screen mappings and the current position against the confirmed corridor. After calibration, use the screen selector for preview and tasks. In the SDK, give each screen a distinct `id` and `screenId` in `RobotArmDevice`, with the same physical `camera`.

The speaker icon in the top toolbar enables or mutes Chinese/English browser speech and short progress tones. Prompts cover phone display requirements, marker-capture countdowns, camera mapping and installation teaching. Before Fast sampling, the confirmation reminds you to secure the phone flat and keep your hands off it. During motion, listen for travel to the reference, grid sampling, hover and contact boundary checks, and camera avoidance. If the arm prepares to lift and return after a sampling or fit check, the page announces the return and shows it in the progress panel. A quality review, manual Safe Position, batch placement or result awaiting acceptance each has its own prompt. Motion warnings take priority over routine progress, and robot faults and stop outcomes have the highest priority. Speech follows the interface language, requires browser activation, stays silent in hidden tabs and never blocks robot commands.

Targets use a 10% inset and aim to cover 60% of the full screen. **Fast** (sliding) is selected by default. **Regular** probes each point separately at 10% of the configured action speed and acceleration, then uses 25% for the final sampling press. During grid sampling, the phone mirrors the web diagram with nine numbered targets connected in sampling order, a blue ring around the current target and green dots at recorded touch locations. If the first fast grid point reports no touch, one retry moves the target 3 mm toward the measured initial touch without extending the descent limit. If fast collection fails, confirm the switch to Regular to start a fresh collection. In Fast mode, confirm in one checkbox that the screen is fixed and horizontal and the workspace is clear. Use **Previous Step** in arm calibration to review earlier measurements, then **Next** to return to the current step.

Refreshing the single-screen calibration page reopens the current attempt, including its measurements or saved result. You can cancel while a boundary check is pending. If a run is interrupted, the page shows the affected step and offers **Check Recovery** when the controller requires it. In the standalone SDK page, choose **Finish Calibration** after saving to return the result to your script. Starting a new SDK calibration opens a fresh attempt even when the screen has a saved profile.

Safe Position verification uses the phone's reported browser viewport and the observed checkerboard to exclude system bars outside the page. It tolerates scattered pattern misses while still requiring each interior tile to respond. If a capture yields a failed visibility measurement, the camera takes one more set of frames at the same position before the search continues. Saved screen results and pending shared Safe Position verification appear separately in the batch panel. When verification is pending, the operator can confirm the current shared Safe Position after checking the live view. The controller checks the stationary pose against the parking constraints and records the confirmation without moving the arm.

When every screen on the camera is ready, select **Finish calibration and return** to return to the Playground. The workspace checks the current accepted calibration before opening tasks.

## SDK & Adapters

See the [SDK example](./examples/mg400/run.mjs). `RobotArmDevice.perform(action)` executes an absolute tap, long press, swipe or drag in screen pixels; the Device resolves the accepted calibration and camera mapping itself and rejects points outside the screen. To support another arm, implement `RobotArmAdapter` from `@midscene/arm-kit/adapter-development`; refer to the [MG400 adapter](./packages/adapter-mg400/src/mg400.ts).

## Project Structure

```text
packages/arm-kit/           Node.js SDK
packages/adapter-mg400/     MG400 adapter
packages/calibration-ui/    Calibration UI
packages/shared/            Shared types and utilities
packages/playground/        Reusable Playground
apps/playground/            MG400 Playground launcher
examples/mg400/             SDK examples
```

Calibration code is in `packages/arm-kit/src/calibration`: phone and camera setup, sample collection and fitting, and boundary verification.
